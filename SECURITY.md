# Security policy

## Reporting a problem

Do not open a public issue for a suspected vulnerability. Use GitHub's private
vulnerability reporting option when it is enabled for the affected repository.
If no private channel is visible, avoid posting exploit details publicly.

Include the affected path and version, reproduction steps, realistic impact, and
a minimal proof of concept with secrets removed. Reports are reviewed for scope,
reproducibility, and impact.

## Scope

This policy covers code published in this repository. External services shown in
badges or links are governed by their own security policies.

## Safe harbor

Good-faith research should avoid privacy violations, service disruption, data
destruction, persistence, and access beyond what is required to demonstrate the
issue. Stop testing and report immediately if sensitive data becomes accessible.
